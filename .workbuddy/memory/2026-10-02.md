## Customer 模型 serial_no 字段迁移问题
- 用户误以为改 Model `$fillable` 后 make:migration 会自动带上字段。Laravel 不会根据 Model 自动 diff 生成迁移（`$fillable` 只是批量赋值白名单）；make:migration 只生成空壳，字段必须手写进 up()/down()。
- 用户已生成两个空迁移且已执行过（migrations 表有记录），所以一直"没有更新"。
- 修复：填充 2026_10_02_044425_add_customer_table_serial_no.php（up: string('serial_no')->nullable()；down: dropColumn）；删除重复空迁移 052328_add_customer.php；清理 migrations 表两条记录；composer require doctrine/dbal（Laravel 8 + SQLite 执行 dropColumn/改列必需，否则报 AbstractSQLiteDriver not found）。
- 插曲：曾出现"列已存在但 migrations 表无记录"的不一致状态（此前失败回滚所致），通过回滚重建 customers 表 + 重跑迁移对齐。回滚重建会清空该表数据（当时为空表，无影响）。
- 教训：迁移已执行后修改其内容不会被重跑，需要 migrate:rollback 或手动清理 migrations 表记录。

## Customer 加 queue_key / batch_no 字段迁移报错
- 报错：`table "customers" already exists`——用户对已存在的表用了 `Schema::create` 整体重建。给已有表加列必须用 `Schema::table`。
- 用户原文件的 down() 也有 bug：先 `dropIfExists` 再 `Schema::table` 改已不存在的表，回滚必挂。
- 注意：serial_no 列此前已入库（旧迁移已执行过），新迁移里不能再 add，否则 duplicate column。判断要不要加列以数据库实际结构为准，不是看 Model。
- 修复：删掉错误迁移，用 `make:migration add_queue_key_and_batch_no_to_customers_table --table=customers`（--table 自动生成 Schema::table 骨架），只加 queue_key + batch_no；migrate 后验证 5 列齐全、状态全 Yes。
- 插曲：用户自己同时也在终端敲了同样的 make:migration 命令，导致我生成时报 "class already exists"——改库前先确认没有并行操作。

## 字段类型重构：serial_no / batch_no / current_no 改 integer
- 需求：serial_generator 的 batch_no、current_no 和 customers 的 serial_no、batch_no 改 integer 类型。
- 关键决策：posts 有 4 条数据、users 有 1 条，**不能用 migrate:fresh**；采用 doctrine/dbal 的 `->change()` 新增 alter 迁移（已装 dbal），SQLite 下 change() 底层重建表、数据保留。
- 操作：新建 090000（serial_generator 两列）、090100（customers.batch_no）、090200（customers.serial_no）三个 change() 迁移；恢复被用户删除的 044425 serial_no 迁移文件（直接写成 integer 版）并补登记执行记录。
- 教训：**migrations 表记录与迁移文件是两回事**——用户删了 044425 文件但记录还在，导致我补登记时插入了重复行（已去重清理）。判断迁移是否已执行要看记录，不是看文件在不在。

## 预约取号功能（ReserveController@add）
- 路由：POST /api/reserve，参数 key。
- 逻辑：查 serial_generator 中 queue_key=key 且 need_reset=0 的记录（lockForUpdate + DB::transaction 防并发）→ 有则 current_no+1 作为 serial_no 并回写；无则取该 key 历史 max(batch_no)+1 开新批次（need_reset=0、current_no 初始 0），serial_no=1，取号后 current_no 同步为 1（与已有分支"取号后 current_no 加一"保持同一逻辑）。最后写 customers 一条，返回 queue_key/batch_no/serial_no。
- 模型修复：SerialGenerator 需显式 `protected $table = 'serial_generator'`（实际表名是单数，Eloquent 默认复数化会找 serial_generators）；$fillable 补 need_reset；加 integer casts。
- 已通过 tinker 冒烟验证四种场景（新开批次、连续取号、办结后开新批次），测试数据已清理。

## add_is_finish 迁移执行失败修复
- 报错：`There is no column with name 'is_finish' on table 'customer'`。两个 bug：① 表名写成单数 `customer`（应为 `customers`）；② 新列加了 `->change()`——change() 只用于**修改已存在的列**，新增列不能用。
- 修复：改表名、去掉 change()、补 down()（dropColumn）。migrate 成功，is_finish integer 已入库。
- 已建议（未实施）：0/1 标志位可用 `$table->boolean()` + 模型 `$casts` 更地道。
